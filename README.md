## Средняя сложность

### Задание 4. TDD для калькулятора

`Calculator` реализует сложение, вычитание, умножение и деление. Деление
на ноль (в том числе `0.0` и `-0.0`) вызывает `ValueError` с понятным
сообщением. Тесты проверяют положительные и отрицательные числа, ноль,
порядок операндов и погрешность вычислений с `float` через `pytest.approx`.

TDD отражён в истории ветки `feature/task04-tdd`: коммит
`test: add calculator specification before implementation` содержит тесты,
а следующий `feat: implement calculator to satisfy tests` — реализацию.

```
2 + 3 = 5
10 - 4 = 6
6 * 7 = 42
9 / 2 = 4.5
1 / 0 -> деление на ноль запрещено
```

### Задание 6. Настройка flake8

Файл `.flake8` задаёт максимальную длину строки 79 символов, исключает
служебные каталоги и включает статистику. Проверяются корневые модули,
тесты и исходники собственного пакета.

```
$ python -m flake8 .
(команда не вывела ни одной строки)
код возврата: 0
```

### Задание 10. Архитектура MVC

Отдельный документ `task10_mvc_architecture.md` описывает приложение
«Библиотека»: Model отвечает за книги, правила и SQLite, View — за окно

## Повышенная сложность

### Задание 5. TDD для API

FastAPI-приложение «Библиотека» поддерживает:

- `POST /books` — создание с кодом 201;
- `GET /books` — список и необязательный фильтр `author`;
- `GET /books/{id}` — получение книги либо 404;
- `PUT /books/{id}` — полное обновление;
- `DELETE /books/{id}` — удаление с кодом 204.

Pydantic очищает внешние пробелы, проверяет обязательные строки и диапазон
года `0..2100`; некорректный запрос получает 422. Фабрика `create_app`
создаёт независимое хранилище для каждого приложения, поэтому тесты не
зависят от порядка запуска. Ветка `feature/advanced05-api-tdd` также
содержит сначала тестовый коммит, затем реализацию.

16 API-тестов используют `TestClient`: проверяются успешные ответы,
фильтрация без учёта регистра, все операции CRUD, отсутствующие id,
пять вариантов невалидного ввода и изоляция хранилища.

### Задание 9. Собственный пакет для TestPyPI

Создан пакет **`poloshkov-mtp-utils` 1.0.0** с исходниками в `src` и
метаданными `pyproject.toml`. Он не имеет внешних зависимостей и предоставляет
`extract_words`, `word_count`, `top_words`, `character_count`. Поддерживаются
Unicode, дефис внутри слов и детерминированная сортировка частот.

10 тестов проверяют пунктуацию, регистр, кириллицу, пустой ввод, границы
параметра `limit`, подсчёт символов и версию пакета. Собраны:

- `poloshkov_mtp_utils-1.0.0-py3-none-any.whl`;
- `poloshkov_mtp_utils-1.0.0.tar.gz`.

Оба файла прошли `twine check`. Wheel дополнительно установлен в чистое
виртуальное окружение: импорт и вычисления выполнены успешно.

Фактическая загрузка требует личного API-токена TestPyPI, который не
должен храниться в репозитории. После установки токена в переменные
окружения публикация выполняется командами:

```powershell
cd advanced09_package
$env:TESTPYPI_API_TOKEN="личный_токен"
python -m twine upload --repository testpypi dist/* `
  --username __token__ --password $env:TESTPYPI_API_TOKEN --non-interactive
Remove-Item Env:TESTPYPI_API_TOKEN
```

## Как запустить

```bash
python -m pip install -r requirements-dev.txt
python task04_calculator.py
uvicorn advanced05_books_api:app --reload
python -m pytest -v
python -m flake8 .
python -m build advanced09_package
python -m twine check advanced09_package/dist/*
python collect_demo.py
```

Работа велась в feature-ветках, каждая слита в `main` merge-коммитом
(`--no-ff`). Сообщения коммитов — по Conventional Commits.
